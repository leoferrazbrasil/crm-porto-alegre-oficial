# CRM Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build email/password authentication and protected admin sessions for the Porto Alegre Oficial CRM.

**Architecture:** Use Supabase Auth through `@supabase/ssr` for cookie-backed browser and server clients. Next.js `proxy.ts` refreshes the session and applies coarse redirects, while server helpers validate the authenticated user and active `admin` profile before rendering CRM pages.

**Tech Stack:** Next.js 16 App Router, React 19, Supabase JS, Supabase SSR, TypeScript, Vitest.

## Global Constraints

- First user is `leonardoferrazbrasil@gmail.com`.
- Initial password is `202122`, to be changed after first access.
- Public signup is not exposed in the CRM UI.
- Only active `admin` profiles can access the CRM in this step.
- Keep dashboard data mocked in this step.
- Do not add Instagram, WhatsApp, or other external integrations.
- Do not expose service role keys or secrets to browser code.
- Run `npm test`, `npm run lint`, and `npm run build` before completion.
